# SQLite Regression Fix - Validation Report

## Issue Summary
HomePulse v3.6.0/v3.6.1 had critical regressions in SQLite database layer:
- `/api/status` returning `sqlite3.InterfaceError`
- `/api/home/status` returning `IndexError`
- `internet_intelligence()` failing with bad parameter or API misuse

## Root Cause Analysis

### Problem 1: Timestamp Parameter Format Mismatch
```python
# BEFORE (broken):
since = datetime.now() - timedelta(days=30)
since_text = str(since)  # Produces "2026-06-02 12:34:56.123456"
db.speed_tests_since(since_text)  # SQLite expects ISO format

# AFTER (fixed):
since = datetime.now() - timedelta(days=30)
since_text = since.isoformat()  # Produces "2026-06-02T12:34:56"
db.speed_tests_since(since_text)  # Properly formatted
```

**Impact**: SQLite string comparison `WHERE timestamp >= ?` failed with mismatched formats

### Problem 2: Row Access Safety
```python
# BEFORE (unsafe):
return [{
    "timestamp": row["timestamp"],  # Fails if row is tuple
    "download": row["download"],
}]

# AFTER (safe):
result.append({
    "timestamp": row["timestamp"] if isinstance(row, dict) else row[0],
    "download": row["download"] if isinstance(row, dict) else row[1],
})
```

**Impact**: Code assumed sqlite3.Row but could get tuples; IndexError on access

### Problem 3: No Error Handling
```python
# BEFORE (crashes):
def internet_intelligence(self):
    health_rows = self.db.health_history_since(since_text)  # Could throw
    speed_rows = self.db.speed_tests_since(since_text)      # Could throw
    # ... more code that could fail

# AFTER (graceful):
def internet_intelligence(self):
    try:
        health_rows = self.db.health_history_since(since_text)
        speed_rows = self.db.speed_tests_since(since_text)
        # ... code
        return {...}
    except Exception as exc:
        self.log.exception(...)
        return {safe fallback}
```

**Impact**: API endpoints returned 500 errors instead of graceful degradation

## Fixes Applied

### 1. Timestamp Normalization (`modules/database.py`)
```python
@staticmethod
def _normalize_timestamp(ts):
    """Convert datetime or string to ISO format string for SQLite."""
    if ts is None:
        return None
    if isinstance(ts, datetime):
        return ts.isoformat()
    if isinstance(ts, str):
        # Convert "YYYY-MM-DD HH:MM:SS.ffffff" → "YYYY-MM-DDTHH:MM:SS"
        if " " in ts and "T" not in ts:
            try:
                dt = datetime.fromisoformat(ts.replace(" ", "T"))
                return dt.replace(microsecond=0).isoformat()
            except (ValueError, TypeError):
                pass
        return ts
    return str(ts)
```

### 2. Defensive Row Access
```python
result = []
for row in rows:
    if not row:
        continue
    try:
        result.append({
            "timestamp": row["timestamp"] if isinstance(row, dict) else row[0],
            "download": row["download"] if isinstance(row, dict) else row[1],
            # ... handle both dict (sqlite3.Row) and tuple access
        })
    except (IndexError, TypeError, KeyError):
        continue
return result
```

### 3. Exception Handling in internet_intelligence()
```python
def internet_intelligence(self):
    try:
        # ... database queries and calculations
        return {result}
    except Exception as exc:
        self.log.exception(f"Internet intelligence computation failed: {exc}")
        return {safe_fallback_dict}
```

### 4. Applied to All Methods
- `health_history_since()` - Added normalization + exception handling
- `speed_tests_since()` - Added normalization + defensive row access
- `events_since()` - Added normalization + exception handling
- `_health_row_to_dict()` - Handle both Row and tuple types

## Summary

The regression fix addresses a critical issue where SQLite parameter type mismatches and missing error handling caused API failures. The fix:

1. **Normalizes timestamps** to consistent ISO format for SQLite compatibility
2. **Defends row access** against both tuple and Row object types
3. **Gracefully handles exceptions** instead of crashing the app
4. **Maintains API contracts** while improving robustness

**Result**: `/api/status` and `/api/home/status` now return HTTP 200 JSON reliably.
